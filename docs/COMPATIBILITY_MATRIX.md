# Compatibility matrix

**NATIVE** means checked through public BZCC. **BAKED** means an editor operation is materialized into a supported native format. **EDITOR_ONLY** means BZMAG state only. **EXPERIMENTAL** means evidence is incomplete. **UNSUPPORTED** means unavailable in the indicated profile.

| Surface | Profile and status | Evidence or boundary |
|---|---|---|
| Layout registry (capability model) | NATIVE gating of every BZN read and write | `app/formats/bzn_layouts.gd` is the single source of truth: binary-1192, binary-1196, binary-1197 and text-1200 entries each hold header fingerprint, framing, boundary discovery, invariants, capability statuses and recorded evidence. The codecs and Playtest launcher consult it; a matching header number alone never grants a write. `res://tests/bzn_layout_profiles.gd` covers positive/negative recognition, truncated and renumbered-spoof samples, capability classification, playtest routes and package-level refusal; the suite chains it through `Test-BznLayouts.ps1`. |
| BZN 1192 binary map | NATIVE read/paths/objects, ENGINE_PLAYTEST NATIVE, BAKED template-cloned object-count edits | Original BZN and 23 paths kept. After adding a matching flat TER to a copy, 2.0.185 reached MISSION / RUN with the mission script disabled. VRV's layout converter rejects version 1192, so it launches natively and never converts. Duplicating an in-map object before the 640-byte `groupTargets` boundary with a unique pointer ID also reached MISSION / RUN on 2.0.185; inserting classes not yet in the map stays pending. |
| BZN 1196 late binary layout | UNSUPPORTED as a raw 2.0.185 launch; READ/paths/objects NATIVE, CONVERT_TO_185 NATIVE | VRV found an extra Craft field in Brave. The verified playtest route goes through `bzn_compat` conversion; the launcher now refuses a raw or VRV-less launch instead of trying it ("SAVEGAME CORRUPT" from the unconverted layout). The editor's normal export preserves the original BZN bytes. |
| BZN 1196 public layout | NATIVE for adapted Brave on 2.0.185 | VRV converted one Craft record in a private snapshot. The game entered MISSION / RUN with original script selection enabled. Path point edits, whole-path edits, object transform edits, template-cloned object insertions and unreferenced removals carry 2.0.185 MISSION / RUN acceptance; inserting classes not yet in the map stays pending. |
| BZN 1197 binary map | BAKED existing path edits; object operations UNSUPPORTED; engine compatibility EXPERIMENTAL | VSR fixtures match the independent BZNTools path counts. A Terrace 2 export reimports with the changed label and all other BZN bytes intact. The registry declines 1197 object tables and the 2.0.185 launch route until they are verified. |
| BZN 1200 | EXPERIMENTAL recognition only; binary edits UNSUPPORTED | The available Bolt sample is a text save. The registry classifies it, the package loader refuses it for editing, and its paths remain opaque to the binary editor. |
| TER v5 heights | NATIVE on the verified 2.0.185 case | Signed bounds, float heights, 2 m samples. Modified Brave loaded in-game. Independent decoder confirmed affected samples. `Terrain.create_flat()` / New Map Wizard also generate Stock-first native flat TER v5 directly without VRV/VSR templates. |
| Brush and graph terrain | BAKED | Raise/lower, flatten, smoothing and procedural output change TER heights. BZCC loaded both a brush export and a graph-baked export. The Advanced Slope Studio extends the same height lane: exact-angle ramps and the ten profile stamps bake through the identical command pipeline (one undo step), and an exported 15-degree ramp decoded through the independent VRV oracle shows only the counted height samples changed. |
| TER RGB, alphas, flags, tiles | BAKED RGB and tile IDs, NATIVE preservation of other channels | Color and tile edits reimport through the native codec. Tests compare the pre-paint bytes of every unaffected lane. Preview uses all 16 textures on Brave. |
| TRN / INF / DES | NATIVE passthrough for verified package | TRN and INF text read into metadata. Verbatim export. DES remains opaque. |
| WAT v5 | NATIVE read, preview, coverage and elevation editing with full engine acceptance | WAT decodes on verified v5 files (2,416-byte prefix + one mask bit per 16 × 16-sample terrain block, layer heights at `16 + 160 × bit`). Coverage strokes and per-layer elevation edits share undo, persist in BZMAG and export as an in-place WAT patch verified byte-for-byte against the codec re-encode and by re-import. A Brave export with only water edits carried full in-game MISSION / RUN acceptance with zero `SAVEGAME CORRUPT` lines (2026-11-21 playtest). Water simulation, flow and non-v5 WAT versions remain unproven. |
| SKY / DDS | NATIVE passthrough, fields opaque | Snapshot carries exact bytes. The game reports loading the original SKY. The editor decodes supported DDS material formats; per-field SKY editing is out of scope for 2.0.185 (see ENGINE_LIMITATIONS). |
| Map objects, scrap and pools | NATIVE transform, template-cloned insertion and unreferenced removal on verified binary placements (1192/1196); arbitrary new-class synthesis PENDING; EDITOR_ONLY static preview | Relocated, duplicated (`morock03`, `ivtank_vsr`) and removed (`morock03`) Brave/blank placements export before the 640-byte `groupTargets` mission boundary with unique `kind=8` pointer IDs, re-import identically, and reach MISSION / RUN in 2.0.185 with zero `SAVEGAME CORRUPT` lines. Object operations stay registry-gated (1197 refused), pointer-referenced removals are blocked, and synthesizing new ODF classes without an in-map template remains pending. Brave resolves 76 native meshes including eight pools. |
| Sound points | NATIVE structured `vrvsnd:` label authoring, duplication and BZN export/re-import in verified binary placements (`1192`/`1196`); VRV-managed runtime playback | Objects whose label carries VRV's `vrvsnd:<sound>:<volume>:<range>:<interval>:<jitter>:<pitch>:<near>` serialization can be inspected and edited through `app/tools/sound_editor.gd` (`MapDocument.format_sound_point`, `set_object_label` + `object_label_edits`, clearing the `0x800000` auto-label bit on custom labels in `bzn_objects.gd`), duplicated from an in-map object template, persisted in BZMAG, and exported/re-imported identically in native BZN. Inserting `vrv_sndpoint` from scratch without an in-map template remains pending, and runtime audio playback requires the VRV client runtime. |
| Named AI paths | NATIVE point edits on verified 2.0.185 profile, BAKED whole-path edits in verified tables | The game loaded Brave with an inserted patrol point and loop type. Whole-path creation and removal reimport with stable existing IDs and unchanged surrounding bytes. BZMAP checks known BZN references and local mission text files. Dynamic mission code requires a playtest. |
| Photoshop-style layers / graph | EDITOR_ONLY authoring, BAKED height, RGB and base tile ID outputs | Layer parameters, typed links and order in BZMAG. Preview is temporary. One bake applies all connected outputs to TER. |
| Volumetric cuts, caves and true terrain overhangs | UNSUPPORTED by TER heightfield | Supported terrain has one sample height per X/Z. Prop workflows need separate proof. |
| Newer BZCC executables | EXPERIMENTAL | No newer executable was run in this cycle. |

See the [engine run and hashes](EVIDENCE.md).
