# Format research

## TER v5

The wire contract agrees with VRV `src/shared/TerrainFile.h` at e4ed71d and independent fixture decoding. Bytes 0–3 are `TERR`. A little-endian unsigned 32-bit version follows. Offsets 8, 10, 12 and 14 hold signed little-endian 16-bit minimum X/Z and exclusive maximum X/Z, in 2 m units. A sample at index (i, j) represents world X/Z = 2 × (minX + i, minZ + j). Width and depth in samples must be positive multiples of 16. The current decoder caps the grid at 4,194,304 samples.

The body is tightly packed, row-major 16 × 16 blocks with X fastest in the block list and sample payload. Each starts with eight encoding flags. Clear means one value for that block and set means 256 values. Layers are float32 height, RGB8, three independent 8-bit texture alpha lanes, one 8-bit point flag field, a packed uint16 with four texture IDs (lowest four bits are the base tile), and a uint16 draw mask. The last two layers are block-wide in the reviewed profile. The codec checks exact byte consumption and finite heights. Exports rewrite only the height, RGB, or tile fields that changed. Untouched layers and blocks retain their source bytes. **HeightGranularity** is applied to new height edits independently of binary float32 encoding.

Brave's TER has bounds (-512, -512, 512, 512) and 1024 × 1024 samples. TRN gives 4096 m width and 8 m grid spacing. The 2.0.185 game log agrees with the TER and reports a 2048 m square starting at (-1024, -1024).

## BZN and named paths

Both fixtures start with ASCII version, save type, and binary marker lines followed by framed binary records. `BZNParser/Tokenizer` and `Battlezone/AiPath.cs` distinguish record types from lengths. The reviewed binary path table has a preceding signed 32-bit count. Each record carries the framed label `AiPath`, a 32-bit object identifier, a counted label, a signed point count, a vector array of little-endian float32 X/Z pairs, and a 32-bit path type. VRV `EditorPath.h` names types 0 one-way, 1 round-trip, 2 loop. The inspector refuses mismatched record lengths. Display Y is derived from terrain. Do not infer closure or required names from labels alone. Both supplied `edge_path` records are type 0 and have 13 and 2 points respectively.

BZNTools 7ee7de2 parsed Brave (76 entities and 23 paths) and the blank (1 entity and 23 paths). For binary `save:false` with preservation enabled, its serialized output matches the original prefix and omits an 8,031-byte suffix in both cases. BZMAP keeps BZN byte-identical unless the user edits a supported path. In that case it patches the chosen path fields, keeps the existing object ID, and verifies the original bytes after the table. The suffix semantics remain open.

The same path record framing is verified on binary 1197 map saves. BZNTools reports 16 paths in VSR Terrace 2 (`vsrterrace2.bzn`) and one in AdMemorium Volcano (`admemvolcvsr.bzn`); read-only copies of both plus the text 1200 `STBolt.bzn` live under `map_references/vsr_1197/` and `map_references/stbolt_1200_text/` (copied verbatim from the VSR workshop originals). `res://tests/bzn_path_profiles.gd` checks both counts and the first path against those reads, then patches Terrace 2 through native export with byte identity before and after the changed field. `res://tests/bzn_layout_profiles.gd` now classifies every fixture through the layout registry (`app/formats/bzn_layouts.gd`), asserts the recorded capability statuses, refuses spoofed and unregistered headers, locks the object codec to 1192/1196, and pins the 2.0.185 playtest routes (1192 native, 1196 converted, everything else refused). The suite chains both through `tools/Test-BznLayouts.ps1`. The 1197 result covers the path table and reimport. The verified game launch profiles are listed separately in the compatibility matrix.

VRV's reviewed layout converter removes the later Craft `ejectRatio` record even when both files say 1196. VRV also documents a later `isDamped` record. The Playtest adapter stores the conversion sidecar separately. [VRV source and game evidence](REFERENCE_INVENTORY.md).

## TRN and package graph

- BZN references mission identity, a terrain stem, mission DLL and object types. For Brave the DLL string is `strategy02.dll`. The game resolves referenced ODF, models and textures through active resource streams. Workshop and VRV/VSR dependency lookup is a distinct stage.
- TER provides geometry and blending indices. TRN supplies default geometry settings, height granularity, terrain texture names, sky assets, fog/light/music settings, and mission DLL settings. The editor reads TRN keys while exporting the input bytes untouched.
- WAT v5 starts with `WATR`, version and four signed sample bounds. Reviewed files have a 2,416-byte prefix followed by one spatial bitmask byte per 16 × 16-sample terrain block. Each active bit selects a layer height at `16 + 160 × bit`. Brave has 222 layer-1 blocks at 135 m. BZTC `coop_bztcss12` has 459 and 54 blocks at 30 and 297.1 m, and `Zjourney` has four layers including overlapping masks. The preview skips unusable layer heights. Water simulation and editing remain open.
- SKY starts with `_YKS` and a little-endian version 4 in both fixtures. Their SKY files are 7,068 bytes. The game log shows separate parsing for rain, lightning and splat. Per-field editing remains unverified.
- INF gives display metadata, network defaults and local preview/description filenames. The application indexes its fields and preserves raw bytes. The three INF filename fields are included when resolved to local files. DES is description text (the Brave sample opens with pool information). DDS files have normal DDS magic and remain opaque.
- In the verified binary saves, the mission DLL name follows the 640-byte `groupTargets` record. The Bolt text save names the same field `dllName`. Playtest resolves those direct DLL references and the same-stem Lua file for `LuaMission.dll`. Search order is map snapshot, linked profile folders, VRV dependencies when configured, and stock game resources. Dynamic Lua imports, internal DLL dependencies, ODF inheritance and audio/model references can add further dependencies.

For the reviewed binary BZN profiles, the object reader checks the declared count and reads each ODF name, team field, label/sequence and 64-byte native placement matrix before the path table. The asset source follows local ODF inheritance for geometry and scale. The local C++ adapter uses VRV's `MeshIcon.h`, `MeshSurface.h` and `CrosshairSize.h` to read baked MSH and supported DDS. The editor reads remaster `.material` diffuse names and builds static meshes in native placement. It resolves the 76 records and eight pool objects on Brave. Animation, skinned deformation and in-game LOD selection are outside this preview. The renderer uses the actual TER material selections and alphas, with approximate projection and box lighting.

The supplied blank has BZN/TRN/INF/SKY/WAT. VRV `MapCreator.h::Ter` explicitly generates a TER from a verified flat template. Its host notes that fallback ground from TRN alone did not complete the BZN load in the reference run. **New Map** uses `tools/New-FlatTerrainSnapshot.ps1` to validate a supplied uniform template against TRN dimensions, origin and flat elevation. The editor reopens the staged package before placing it in the selected folder. 2.0.185 reached MISSION / RUN with the reference template and the original 1192 BZN under `/startedit /noscript`.
